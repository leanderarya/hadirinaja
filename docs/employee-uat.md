# Employee UAT: isolated local MySQL

This setup uses a separate MySQL 9.7.1 process. It does not point Laravel at the shared `hadirinaja_dev` / `hadirinaja_test` databases or alter the Homebrew MySQL service.

## Instance

- MySQL binary: Homebrew MySQL 9.7.1
- Private support directory: `~/Library/Application Support/HadirinAja/uat-mysql-9.7.1`
- Datadir: `~/Library/Application Support/HadirinAja/uat-mysql-9.7.1/data/instance`
- Socket: `~/Library/Application Support/HadirinAja/uat-mysql-9.7.1/run/mysql.sock`
- TCP: `127.0.0.1:3307`
- Database: `hadirinaja_uat`
- Laravel account: `hadirinaja_uat_app`, with privileges only on `hadirinaja_uat.*`
- Binary logging: instance-local `ROW` format, with `log_bin_trust_function_creators=ON`; the setting is not applied to the shared server.
- The instance binds to loopback, disables MySQL X Protocol and local infile, and retains its datadir when stopped.

Generated root/app/Employee credentials, MySQL configuration, binlogs, Laravel cache/session/log/storage files, and the recorded server UUID stay under the private support directory with owner-only permissions. Employee login details are in `secrets/employee-login.txt`; this documentation intentionally contains no passwords.

## Lifecycle

Run once to initialize and start the separate server:

```sh
backend/scripts/uat-mysql.sh init
```

Then use these commands as needed:

```sh
backend/scripts/uat-mysql.sh start
backend/scripts/uat-mysql.sh verify
backend/scripts/uat-mysql.sh stop
backend/scripts/uat-mysql.sh status
```

`init` refuses an existing instance directory or occupied port. `start` and `reset` verify the MySQL identity, local binlog settings, and schema-scoped app grants. `stop` verifies the MySQL identity and local configuration before graceful shutdown. No lifecycle command stops an unrecognized process. The datadir persists across stops and reboots; start the server manually after reboot. No LaunchAgent or shared service configuration is installed.

The explicit destructive reset is confined to the verified `hadirinaja_uat` schema:

```sh
backend/scripts/uat-mysql.sh reset --confirm=hadirinaja_uat
```

It runs `migrate:fresh` and the dedicated `EmployeeUatSeeder`; it does not invoke the existing `DatabaseSeeder`.

## Employee fixtures

| Account | Purpose |
| --- | --- |
| `uat.checkin@example.test` | Linked Employee, current-day policy/schedule, no active session; read API reports check-in eligibility. |
| `uat.checkout@example.test` | Linked Employee with a synthetic active check-in session; read API reports checkout eligibility and unresolved session state. |
| `uat.foreign@example.test` | Employee in a separate tenant with a request used to check tenant isolation. |

Both main-tenant Employees have one effective Outlet assignment at UAT Central. UAT Riverside uses Personal mode and has no Employee assignment. The primary Outlet has a current-day eligibility rule and a future published planner week with work/rest entries. The check-in Employee has pending, approved, and rejected leave requests. The checkout session has an expired-evidence tombstone; no evidence file is written. The active session is generated by the seeder's application service for the checkout UI fixture; acceptance checks must not POST check-in or check-out.

The Owner account is `uat.owner@example.test`. Credentials for all fixture accounts are generated privately during `init`, not committed or printed by the setup commands.

## Run API and frontend

In one terminal, start the Laravel API; it binds only to port 8001. The wrapper uses PHP's built-in server directly so the dedicated database and storage environment is inherited by each request:

```sh
backend/scripts/uat-mysql.sh api
```

In another terminal, start Vite; `vite.config.ts` binds to `127.0.0.1:3001` and proxies API/Sanctum traffic to `127.0.0.1:8001`:

```sh
bun run dev
```

Open `http://127.0.0.1:3001`. The generated private Laravel environment sets the 8001 APP_URL, 3001 CORS/Sanctum origins, the dedicated DB credentials, and a private Laravel storage path. The shared backend `.env` and the repository's UI configuration are not rewritten.

## Verification

```sh
backend/scripts/uat-mysql.sh verify
```

After reset, the script also checks that all migration files are applied, all eight expected triggers exist, each Employee has one distinct Outlet assignment, a published week exists, the checkout account has one active session, the check-in account has all three request statuses, the expired evidence tombstone exists, and the foreign request is not visible in the main tenant schema scope.
