## Numbered findings for Owner approval

### 1. HIGH: readiness-file race makes the concurrency gate intermittent

Rules: R-35, C-4. Files: `backend/tests/Support/approval-operation-worker.php:24`; `backend/tests/Feature/S5/ApprovalConcurrencyTest.php:470` and `:516`.

Exact original failure: `Tests\Feature\S5\ApprovalConcurrencyTest::test_revision_approval_and_reversal_serialize_and_replayed_reversal_is_unique`, `Syntax error`, thrown by `json_decode(..., JSON_THROW_ON_ERROR)` at line 470. The worker uses `file_put_contents` directly on the final readiness path. The parent waits only for `is_file`, then immediately decodes it. Existence can become visible before the JSON write is complete. This is the source-supported explanation for the observed parse failure, not evidence of a failed database approval transaction. The failed read's exact bytes were not retained, so the partial-read cause is not claimed as experimentally isolated.

Reproduce: run the named test repeatedly against a disposable `hadirinaja_test` MySQL socket, including concurrent full-gate workload. One run may pass; this audit observed a full-run failure followed by a focused pass. Minimal proposed fix: publish readiness metadata by writing a sibling temporary file then atomically renaming it, preserving distinct connection IDs, parent-held locks, worker deadlines, and all assertions. Do not add sleeps or weaken JSON decoding. Verify multiple focused runs plus the full suites after approval. No evidence/audit mutation defect was demonstrated by this failure.

### 2. HIGH: correction warning text fails normal-text contrast

Rule: R-25; UI/accessibility contrast rules. File: `src/routes/approvals.tsx:1663`.

At 390 CSS px, pending correction text `Temuan: koreksi menunggu` rendered at 12 px / weight 400, foreground `rgb(230, 93, 119)` on white. Measured WCAG relative-luminance contrast: **3.39:1**, below **4.5:1**. The `text-destructive` token is too light for this text use. Similar error-text uses at lines 1271, 1382, and 1503 deserve the same check, not an assumed blanket failure.

Reproduce: open a pending correction in `/approvals`, inspect the paragraph's computed foreground/background, calculate `(Llighter + .05) / (Ldarker + .05)` using sRGB linearization. Minimal proposed fix: use the existing darker danger-text semantic token for affected normal text, then check all error/status states. Preserve status meaning and authorization behavior.

### 3. HIGH: evidence and map controls miss the Anti-Slop 44 px target

Rule: R-03; mobile-layout minimum-target rule. Files: `src/components/correction-evidence-panel.tsx:209`, `:305`, `:320`, `:344`; `src/components/ui/button.tsx:25`; Leaflet controls in the attendance map integration.

Measured Supervisor detail at 390 px: `Unduh lampiran #1` **151 × 40 px**; `Minta bukti tambahan` **324 × 21 px**. Upload/send evidence controls also measured 40 px tall. Employee attendance map zoom controls measured **30 × 30 px**. Offscreen 1 px skip-link geometry was deliberately excluded: it is visually hidden until focused, not a 1 px visible target.

Reproduce with `getBoundingClientRect()` on the visible buttons/summary and `.leaflet-control-zoom-in` / `.leaflet-control-zoom-out`. Minimal proposed fix: local minimum 44 px targets and appropriate spacing in these operational surfaces, including the supplementary summary and map controls. Do not globally enlarge every `size="sm"` without checking consumers. Update the real-component UI-kit demos if components change. Anti-Slop's 44 px requirement is stricter than WCAG 2.2 AA's general 24 px target criterion; these measurements alone do not prove a WCAG target-size violation.

### 4. HIGH: shared pointer affordance omits native selects and disabled states

Rule: R-39. File: `src/styles.css:248`; native approval status selector in `src/routes/approvals.tsx`.

Computed cursor for the enabled approval status `<select>` is `default`. The base rule sets pointer only for enabled buttons and `[role="button"]`; it omits the other native controls required by the installed rule and a shared disabled `not-allowed` rule. This is an explicit Anti-Slop convention, not a claim that a native select is inaccessible merely because of its cursor.

Reproduce: `getComputedStyle(document.querySelector('select')).cursor` on approvals. Minimal proposed fix: extend the base selector list to the rule's enabled control types and explicit disabled states; preserve text-input selection cursors and verify labels, checkbox/radio, tabs, and native disabled behavior.

### 5. HIGH: operational pages reuse one document title

Rule: R-39 unique page title. File: `src/routes/__root.tsx:28`; attendance, requests, approvals, and kiosk route head metadata.

The browser reported the same `HadirinAja` presensi/operational title for `/attendance`, `/requests`, `/approvals`, and `/kiosk`. This makes tabs and assistive navigation harder to distinguish. Minimal proposed fix: route-specific titles composed with the existing product name; keep one shared fallback. Verify route transitions and refreshed deep links.

### 6. HIGH: active title contains the R-02 banned punctuation

Rule: R-02; copywriting Em Dashes rule. File: `src/routes/__root.tsx:28`.

The shared title contains Unicode U+2014 between product name and description. No Owner-approved voice exception was found. This is a mechanical mismatch with the installed hard gate, not proof of AI authorship. Minimal proposed fix: choose an ordinary title separator while implementing finding 5. Missing-value markers in attendance records need a separate contextual decision and should not be mass-replaced as prose punctuation.

### 7. LOW: stale duplicate return annotation on an evidence authorization method

Rule: R-31; antislop-code Signature Echo / preserve valuable documentation. File: `backend/app/Services/ApprovalWorkflowService.php:803`.
